# 邮件客户端公开契约

本文冻结 `mybevy` 客户端消费 MyServer 玩家邮件接口的边界。服务端权威基线为 MyServer `docs/周边服务/聊天与邮件系统设计.md` 的“冻结的玩家 HTTPS 公网 API”。

## Endpoint 与环境策略

正式环境只消费登录、选角或补发 ticket 响应中的 `services.mail`：

```json
{
  "host": "api.game.zergzerg.cn",
  "port": 443,
  "protocol": "https"
}
```

客户端只使用 descriptor 的 scheme、host 和 port，并固定拼接 `/api/v1/mails`。正式 endpoint 是 `https://api.game.zergzerg.cn:443`，正式 base URL 是 `https://api.game.zergzerg.cn:443/api/v1/mails`；客户端不接受 descriptor 自定义 path，不读取 registry，不硬编码或回退内部 `9003`。

`services.mail = null` 表示邮件能力受控不可用。登录和游戏主链路可以继续，但客户端不得猜测 endpoint。非法 descriptor 同样只禁用邮件能力并保留脱敏错误原因。

本地 HTTP 联调必须同时满足：

- 客户端明确选择 Local MyServer profile；该 profile 的 `MyServerConfig.allow_insecure_mail_http` 为 `true`。
- auth 响应明确下发 `protocol=http` 的 `services.mail` descriptor；客户端仍不自行构造 `127.0.0.1:9003`。
- 可用 `MYSERVER_ALLOW_INSECURE_MAIL_HTTP=false` 关闭 Local profile 的 HTTP 放行。
- Production profile 无论 build 类型和环境变量如何都令该策略为 `false`，因此只接受 HTTPS。

策略在登录、选角和 ticket 刷新响应上统一应用。切环境会清除账号、角色、ticket 和已解析 endpoint。

## 身份边界

四个玩家接口只发送当前 character-bound game ticket：

```text
X-Game-Ticket: <game_ticket>
```

客户端不发送 `Authorization`、service/admin token，也不通过 query 或 body 提交 `player_id`、`character_id`、附件、实例、request ID 或幂等键。服务端从 ticket 取得账号 `player_id`（协议实现可表示为 `playerId`）作为邮件 ownership，从同一 ticket 取得 `character_id`（协议实现可表示为 `characterId`）作为附件发放主体。切换角色不会改变账号邮件归属，但领取附件始终只进入发起请求的 ticket 所绑定角色。

## 固定接口与响应

| Method | Path | 成功响应 |
| --- | --- | --- |
| `GET` | `/api/v1/mails?status&limit&offset` | `{ ok, mails, unread_count, pagination }` |
| `GET` | `/api/v1/mails/:mailId` | `{ ok, mail }` |
| `PUT` | `/api/v1/mails/:mailId/read` | `{ ok, mail_id, status, read_at, already_read }` |
| `POST` | `/api/v1/mails/:mailId/claim` | claim workflow 响应；确认中可以是 HTTP `202` |

列表摘要字段固定为 `mail_id`、`sender { type, id, name }`、`title`、`mail_type`、`status`、`has_attachments`、`created_at`、`read_at`、`claimed_at`、`expires_at`。分页固定为 `limit`、`offset`、`next_offset`；没有下一页时 `next_offset` 为 `null`，不返回 total。

详情在摘要上增加 `content`、`attachments` 和 `claim`。公开附件字段只有 `type`、`id`、`count`、`binded`。claim 摘要字段为 `claim_status`、`already_claimed`、`processing`、`retryable`、`player_retryable`、`attempts`、`result_state`、`error`。

领取状态冻结为：`claimed`、`processing`、`retryable_failure`、`blocked_capacity`、`permanent_failure`、`reconciliation_pending`、`manual_review`。一次用户领取动作只发送一次 `POST /api/v1/mails/:mailId/claim`。HTTP `202`、超时、断连或其他无法确认结果的响应进入 reconciliation：客户端在 `1`、`2`、`4` 秒后分别 `GET /api/v1/mails/:mailId`，直到权威状态收敛或进入明确的人工处理状态；不得重发 claim POST、推断失败或在本地发奖。

时间字段为 RFC 3339 UTC；缺失时间和可选状态使用 JSON `null`。邮件 ownership、内部路由、租约、下游实例和内部错误字段不属于客户端契约。

## 分页与错误

`status` 只接受 `unread`、`read`、`claiming`、`claimed`；`limit` 为 1 至 50，默认 50；`offset` 为 0 至 10000，默认 0。`mailId` 为 `[A-Za-z0-9:_-]{1,64}`。

公共错误 body 为 `{ ok:false, error, message }`。客户端保留服务端稳定 `error` code，并按 HTTP 分类处理：

| HTTP | 稳定语义 |
| --- | --- |
| `400` | `INVALID_PLAYER_MAIL_REQUEST` 或具体输入错误，不重试 |
| `401` | `MAIL_PLAYER_TICKET_INVALID`，重新登录或签票 |
| `404` | `MAIL_NOT_FOUND`；不存在和无 ownership 使用相同结果 |
| `409` / `410` / `422` | 领取状态冲突、`MAIL_EXPIRED` 或永久失败 |
| `429` | `MAIL_RATE_LIMITED`，遵守 `Retry-After`；read 与 claim 分属独立冷却域 |
| `503` | `MAIL_AUTH_UNAVAILABLE`、`MAIL_CLAIM_INTAKE_DISABLED` 或可重试服务不可用 |
| `202` | 已有领取流程处理中或对账中，不按错误处理 |

列表、详情、已读和领取状态以邮件 HTTPS API 与 PostgreSQL 为权威。聊天 `MailNotifyPush` 只使客户端缓存失效并触发权威刷新，push 内容不能直接改写列表、未读数或领取结果。

read 域包含列表、详情、标记已读及 reconciliation GET；claim 域只包含领取入口。某一域收到 `429` 只冷却该域：read 冷却不能阻止一次合法 claim，claim 冷却也不能阻止权威 GET。客户端合并同域的重复刷新，并在 `Retry-After` 到期后至多恢复一次待处理动作。

## 本地与正式联调

本地联调按以下顺序执行：

1. 启动 MyServer auth、mail 及其 PostgreSQL、Redis、NATS 和附件发放所需游戏服务，让 auth 响应向 Local profile 下发 `protocol=http` 的 `services.mail`；不要在客户端手写邮件地址。
2. 客户端选择 Local profile，登录、建角或选角并取得 character-bound ticket；确认邮件请求携带 `X-Game-Ticket`，且 endpoint 来自当前 auth 响应。
3. 验证列表、详情、标记已读、单次领取和 `1/2/4` 秒 GET 对账；再使用两个账号和两个角色验证跨账号 detail/read/claim 均为 `404`、附件只进入请求 ticket 绑定角色且重复领取不重复发放。
4. 在 `project/` 运行 `cargo test mail::tests --lib` 和 `cargo test main_world_mail --lib`；在 MyServer 根目录运行 `node --test tests/mail/mail-two-account-ownership-acceptance.test.mjs`。该服务端验收需要上述真实依赖可用，对应基线提交为 MyServer `11f295e`。

正式联调必须选择 Production profile，并确认 auth 下发的 descriptor 解析为 `https://api.game.zergzerg.cn:443`，所有请求固定落在 `/api/v1/mails` 且没有 HTTP、内部端口或客户端环境变量回退。用正式测试账号完成 GET/PUT/单次 POST 与 push 后 GET 刷新，并核对 TLS、`Retry-After` 和服务端审计记录；不得把桌面 Local 结果当作正式公网验收。

本阶段只完成桌面/本地和服务端契约验证。Android 公网真机上的 DNS、TLS、网络安全配置、前后台恢复及弱网领取对账属于 `summary/07_公网部署后Android真机验收_checklist.md`，不在本邮件功能阶段宣称完成。
