# MyBevy 文档索引

本目录保存 MyBevy 的当前实现说明、技术设计、开发手册和已归档清单。代码、配置和测试是行为事实来源；文档用于说明边界、入口、约定和协作背景。

## 推荐阅读

### 新成员

1. [仓库根 README](../README.md)：项目能力、目录结构和常用命令。
2. [引擎入门使用文档](./引擎入门使用文档.md)：Rust/Bevy 最小启动、桌面运行和 Android 基础流程。
3. [资源工作流](./资源工作流.md)：首包资源、APK 资源和后续下载资源的边界。
4. [协作和开发约定](../CLAUDE.md)：源码目录、构建入口、验收和提交约定。

### 按领域开发

- [界面](./界面/README.md)：页面、面板、输入、主题、声明式文档和 UI 验收。

## 文档类型

| 类型 | 位置 | 用途 |
| --- | --- | --- |
| 当前说明 | 各领域根目录和专题文档 | 说明已经存在的代码、资源、命令和限制 |
| 设计路线 | 各领域专题文档 | 记录尚未实现的目标、取舍和后续阶段，必须明确标注非当前能力 |
| 活动清单 | `summary/` | 当前开发中的任务、验证记录和未完成项 |
| 归档清单 | `docs/<领域>/checklists/` | 已完成阶段的清单副本，保留验收证据和最终完成定义 |

完成清单从 `summary/` 归档到对应领域的 `checklists/` 后，应同步更新领域 README 或本索引中的入口。历史方案不得作为当前实现依据；需要保留时应放入明确的历史归档目录并标注状态。

## 文档维护规则

- 修改源码、资源路径、构建命令、环境变量或验收流程时，同步检查对应领域文档。
- 正式文档开头应说明文档定位、当前实现边界和未实现内容；设计目标不能写成已完成能力。
- 文档路径统一使用中文目录和中文文件名，只有 `README.md` 保留英文文件名；代码符号、协议名和资源路径可保留原有技术命名。
- 新增或移动文档后，检查相对链接、根 README、`CLAUDE.md` 和相关清单的引用。
- 文档改动至少执行 `git diff --check`，并对相对 Markdown 链接做路径检查。
