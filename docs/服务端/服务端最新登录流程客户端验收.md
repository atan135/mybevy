# 服务端最新登录流程客户端验收

本文记录 mybevy 客户端接入 MyServer 密码账号注册、账号登录、选角、character-bound ticket、game proxy 鉴权、进房、断线重连和四属性链路的验收步骤。对应服务端仓库默认位于 `C:\project\MyServer`。

## 身份口径

- `player_id` 是账号级身份，只用于登录、账号安全、封禁、kick、ticket version 和服务端审计。
- `character_id` 是玩法主体。房间、匹配、输入、移动、战斗、背包、transfer、Room snapshot、Frame input、authority local subject 和 Robot Sync/Touch Ripple replay 都必须使用当前 ticket 绑定的 `character_id`。
- `AuthRes.player_id` 仍保存在 `MyServerSession.player_id`，但客户端发给 authority/玩法层的 `MyServerEvent::Authenticated.player_id` 值是当前 `character_id`。这里的字段名沿用 authority 抽象里的 player 术语，不表示账号 `player_id`。
- 缺少 `character_id` 的 legacy ticket、ticket 与当前选角不一致、或 `AuthRes ok=true` 但本地没有选中角色，均按 `MISSING_CHARACTER_ID` / `TICKET_CHARACTER_MISMATCH` 可观察失败处理，不新增 `player_id` fallback。

## 本地栈启动

服务端完整栈：

```powershell
Set-Location C:\project\MyServer
powershell -ExecutionPolicy Bypass -File .\scripts\dev-stack.ps1 -Status
powershell -ExecutionPolicy Bypass -File .\scripts\dev-stack.ps1 -Restart -WithMatch
```

常用端口：

- `auth-http`: `http://127.0.0.1:3000`
- `game-proxy`: KCP `127.0.0.1:4000`，TCP fallback `127.0.0.1:14000`
- `game-server`: `127.0.0.1:7000`，admin `127.0.0.1:7500`
- Redis `6379`、NATS `4222`、PostgreSQL `5432`

联调前先确认没有 dev-stack PID 文件缺失但端口仍被旧进程占用的半启动状态。若存在旧 `game-proxy.exe` 或其他服务监听目标端口，先由主控确认是否停止，worker 不应擅自杀掉他人进程。

## 客户端服务器环境

登录页提供 `本地服 | 正式服` 分段选择，密码注册、账号登录和游客登录共用同一套账号、角色、ticket 和 game proxy 鉴权流程：

- 桌面 Debug 构建默认本地服。
- Release 和 Android 构建默认正式服 `https://api.bevy.zergzerg.cn`。
- 选择只在当前运行期间有效，不写入持久化配置。
- 登录或注册请求发出后服务器选择锁定；切换账号并回到登录页后可重新选择。
- 切换环境会清空 access token、refresh token、角色、ticket、待处理请求、连接状态以及登录/注册输入，避免身份串服。

本地服基础 MyServer 客户端变量：

```powershell
Set-Location C:\project\mybevy\project
$env:MYSERVER_HTTP_BASE_URL="http://127.0.0.1:3000"
$env:MYSERVER_GAME_HOST="127.0.0.1"
$env:MYSERVER_TRANSPORT="tcp"
$env:MYSERVER_TCP_FALLBACK_PORT="14000"
$env:MYSERVER_TICKET_REFRESH_MARGIN_MS="30000"
$env:MYSERVER_AUTO_RECONNECT_WITH_FRESH_TICKET="true"
$env:MYSERVER_DIAGNOSTIC_TRACE="true"
```

正式服已有内置默认值；如需部署期覆盖，使用独立的 remote profile 变量：

```powershell
$env:MYSERVER_REMOTE_HTTP_BASE_URL="https://api.bevy.zergzerg.cn"
$env:MYSERVER_REMOTE_GAME_HOST="bevy.zergzerg.cn"
$env:MYSERVER_REMOTE_TRANSPORT="kcp"
$env:MYSERVER_REMOTE_KCP_PORT="4000"
```

正式服认证必须使用 HTTPS。当前生产 game descriptor 固定为 `bevy.zergzerg.cn:4000/kcp`，宿主只公开 `4000/UDP`，不公开 TCP fallback；服务端登录或选角响应如返回 endpoint，客户端优先使用响应值，因此生产响应不能下发 `127.0.0.1`、容器名或仅内网可达地址。`14000/TCP` 只保留为本地栈按配置启用的开发 fallback，不属于当前生产准入入口。

## 密码账号注册

客户端固定向 `POST /api/v1/auth/register` 发送以下 JSON；服务端 `RegisterDto.displayName` 是可选字段，当前登录页不发送它：

```json
{
  "loginName": "test001",
  "password": "Passw0rd!"
}
```

- `loginName` 会 trim 并转为小写，格式为 `a-z`、`0-9` 或 `_`，长度 `3..=32`。
- `password` 的服务端边界为 `6..=128`；确认密码仅在客户端受控输入组件中用于本地一致性校验，不进入 HTTP 请求、binding、action 参数、日志或诊断快照。
- `201 Created` 且返回 `accessToken` 时，响应与账号登录同型。客户端建立账号 session、清空登录/注册敏感输入、拉取角色列表，并继续选角和 character-bound ticket 流程；注册响应本身不会进入游戏。
- `201 Created` 且 `pendingReview=true` 时，响应只含账号展示状态（例如 `playerId`、`loginName`、`status=pending_review`、`message`），没有可用 access token 或 ticket。客户端停留在注册页显示审核提示，不进入角色选择、Lobby 或 game proxy。
- 本地可提前提示 `INVALID_LOGIN_NAME`、`INVALID_PASSWORD` 和确认密码不一致，但服务端仍是最终权威。已对齐的服务端错误包括 `LOGIN_NAME_EXISTS`、`PASSWORD_REGISTER_UNAVAILABLE`、`IP_BLOCKED`、`PLAYER_BLOCKED`、`BLOCKLIST_UNAVAILABLE`、`MAINTENANCE_MODE` 和 `IP_RATE_LIMITED`；客户端按稳定错误 key 展示它们，网络超时显示可重试的连接超时反馈。
- 注册请求在途时，注册、账号登录、游客登录和环境切换均受同一请求门禁约束。环境切换被拒绝时不会重置 request identity；会话重置后迟到的旧 HTTP 响应因 request ID 不再 pending 而被忽略。

## 登录到鉴权闭环

正式账号路径：

1. 如无测试账号，在客户端选择注册模式，先选择目标服务器环境，再提交账号、密码和确认密码；审核中响应只验收提示与返回登录入口，不继续后续步骤。
2. 如已有测试账号，可在服务端执行 `powershell -ExecutionPolicy Bypass -File .\scripts\seed-auth-test-accounts.ps1`，或直接在客户端登录模式输入账号密码，例如 `test001 / Passw0rd!`，发送 `POST /api/v1/auth/login`。
3. 客户端收到 access token 后拉取 `GET /api/v1/characters`。
4. 若列表为空，创建角色 `POST /api/v1/characters`；若已有角色，读取 `GET /api/v1/characters/{character_id}/profile`。
5. 选择角色，发送 `POST /api/v1/characters/select`，请求体只包含 `character_id`。
6. 客户端保存 `player_id`、当前 `character_id`、`world_id`、角色资料、ticket 和 ticket 过期时间。
7. 使用 character-bound ticket 连接 game proxy，发送 `AuthReq`。
8. 收到 `AuthRes ok=true` 后，session 保存账号级 `AuthRes.player_id`，authority/玩法层使用 ticket 中的当前 `character_id` 作为本地主体。
9. 验证日志只出现 `account_player_id`、`character_id`、`ticket_fp`、`ticket_remaining_seconds`，不出现 access token、ticket、密码或确认密码明文。

游客路径：

1. 登录页点击游客登录，或设置 `MYSERVER_GUEST_ID` 后由自动入口发送 `POST /api/v1/auth/guest-login`。
2. 之后的拉角色、创建角色、选择角色、签票、game proxy 鉴权流程与正式账号一致。
3. 游客升级、登录态持久化和安全存储仍是暂缓项，不作为本轮验收完成条件。

## 进房与玩法输入

### 固定公共主世界

主世界首版复用服务端 `grassland_01`，不创建匹配或动态分线。成功登录、选角并完成 game proxy 鉴权后，可从 Lobby 进入固定 `main-world-public / movement_demo`：

1. Lobby 写入 `MainWorldEntryIntent::Enter`，UI 不直接组装网络包或场景切换。
2. 协调器确认当前 `character_id`、character-bound ticket、环境和鉴权状态后发送 `JoinRoom(room_id=main-world-public, policy_id=movement_demo)`。
3. `RoomJoined(ok=true)` 只确认加房；`RoomStatePush.game_state.scene_id=1` 是兼容性断言，当前 `character_id` 的 `MovementSnapshotPush.entities[].scene_id=1` 与位置是客户端主世界的最终权威。
4. 客户端收到权威快照后才请求 `world.main` scene session；匹配 session 的 `SceneEvent::Ready` 会发送 `SetReady(true)`。
5. 只有初始权威快照、客户端 Scene Ready 和服务端 `ReadyChanged(ok=true, ready=true)` 全部到达，主世界才可操作。
6. 返回 Lobby 时依次冻结输入、发送 `LeaveRoom`、退出 scene session、切回 Lobby。离房应答丢失或短线时仍完成本地清理，并将服务端离房状态记录为未知。

`RoomJoined(main-world-public)` 后，主世界协调器会发送一次幂等 `StartRoom`，以确保公共主城已进入 `in_game` 并取得首个权威快照。服务端只对固定组合 `main-world-public / movement_demo` 放宽匹配房约束：免房主和预 ready 开始门槛、允许 `in_game` 中途加入，并向新加入者定向补发完整 movement recovery snapshot；其他 room/policy 仍保持原有房主、ready 和中途加入规则。

主世界、公共房间和 authority 的常规功能联调使用 Windows `cargo run` 客户端连接本地 MyServer；公网准入另以桌面客户端使用生产 descriptor 完成真实 `4000/UDP` KCP 鉴权、进房、Ready、快照、退出和清理。Android 在本清单只验收候选 APK 的 ABI、启动 Activity、签名状态和首包资源完整性，不以真机网络闭环作为完成门槛。

短线重连使用最新 ticket 重新鉴权并发送 `RoomReconnectReq`；成员已过期则重新加入固定公共房间。kick、封禁、维护、版本不兼容或不可恢复鉴权失败不得自动复用旧 ticket，必须清理到登录页。家园首版本地运行：进入前离开公共主世界，返回时直接重新加入 `main-world-public`，加载失败统一回 Lobby。

## 公网 chat WSS

- auth、选角或补票响应中的 `services.chat` 是唯一客户端入口；当前生产值为 `wss://chat.bevy.zergzerg.cn:443/`。客户端不读取 registry，也不从内部 `9001`、`9011` 或其他端口推导 fallback。
- WebSocket URL、query、subprotocol 和 cookie 均不携带 ticket。连接建立后的首个二进制业务包必须是 `ChatAuthReq(20001)`，character-bound ticket 只写入该包的 token；收到 `ChatAuthRes(ok=true)` 后才发送聊天请求。
- endpoint、ticket、环境、账号、角色或 Logout 改变时推进 generation；旧连接事件和迟到响应不能覆盖新 identity。补票与重连合并，同一轮只发起一次 ticket refresh。
- `services.chat=null`、DNS/TLS 失败、鉴权拒绝或限流只让 chat 进入受控不可用/重连状态，不阻断登录、game proxy、主世界和 mail HTTPS。`MailNotifyPush(20301)` 仅使邮件缓存失效并触发权威 HTTPS 查询，不直接修改邮件事实。

## 公网 mail HTTPS

- auth 响应中的 `services.mail` 是唯一客户端入口；当前生产值为 `https://api.bevy.zergzerg.cn:443`，客户端固定拼接 `/api/v1/mails`，不读取 registry、不接受 descriptor path，也不回退内部 `9003`。
- 列表、详情、已读和领取请求只在 `X-Game-Ticket` 携带当前 character-bound ticket；URL/query、Bearer、Cookie 和客户端提供的 `player_id` 都不是有效身份入口。
- `GET /api/v1/mails`、详情 GET、已读 PUT 和领取 POST 均以 PostgreSQL 权威状态为准。一次领取动作只发送一次 POST；HTTP `202`、超时或断连进入 reconciliation，并在 `1/2/4` 秒通过详情 GET 收敛，禁止重复 POST 或客户端本地发奖。
- `services.mail=null`、HTTPS 超时、`429` 或 `503` 只降级邮箱，不阻断 chat/game/主世界。生产 mail-service 必须启用 `DB_ENABLED=true`；新领取入口与恢复 worker 可独立暂停。离线角色路由返回 `MAIL_CLAIM_ROUTE_UNAVAILABLE` 时保留可解释状态，角色上线后由 recovery worker 继续收敛。

## 生产降级和回滚口径

- chat 灰度通过 auth descriptor 置 null；恢复后必须重新下发公开 WSS descriptor，且核心登录、mail/game descriptor 和健康状态保持正常。
- mail 灰度只暂停新领取入口并保持 recovery；恢复判据为 intake/recovery 均健康、持久 workflow 收敛且内部发信与 game grant 正常。
- UI 远端 generation 超时、签名失败或缓存损坏时保留已验证 generation、回滚 previous generation，或使用首包 approved fallback；不允许激活未验证内容。
- 回滚客户端仍受 minimum protocol、descriptor 校验和稳定错误码约束。Caddy 回滚前后均需通过配置校验、公网健康检查，并确认内部 listener、registry 和 admin 接口未暴露。

最小进房：

1. `MyServerEvent::Authenticated` 发出后，Touch Ripple、Robot Sync 或 authority dev 入口发送 `JoinRoom`。
2. `RoomJoined(ok=true)` 后发送 `SetReady(true)`。
3. `ReadyChanged(ok=true)` 后发送 `StartRoom`。
4. 服务端推送 `RoomStatePush`，客户端 snapshot 的成员列表来自 `RoomMember.character_id`。
5. 玩法输入通过 `AuthorityCommand::SendInput` 进入 MyServer endpoint；客户端不在请求中带账号级 `player_id`，服务端按 ticket/session 绑定角色落主体。
6. `FrameBundlePush` 中的 `FrameInput.character_id` 被映射到 authority `PlayerInput.player_id`，Touch Ripple 和 Robot Sync replay 以该值区分实体。

建议分别验收：

- `ui_touch_room`: 按下、拖动、松开后两端能看到同一帧序的硬边圆和水波拖尾。
- `robot_sync_room`: 两端进入 `arena.robot_sync`，本地机器人移动由 authority frame 推进，Robot Sync HUD 的 player/local subject 为 `chr_*`。
- `AUTHORITY_DEV_MODE=myserver`: 自动登录、进房、ready、start、定时输入仍可串联。

## ticket、断线和服务端控制

需要观察的路径：

- 提前补发：ticket 剩余时间小于 `MYSERVER_TICKET_REFRESH_MARGIN_MS` 时发送 `/api/v1/game-ticket/issue`，请求体必须是当前 `character_id`。
- 断线重连：启用 `MYSERVER_AUTO_RECONNECT_WITH_FRESH_TICKET=true` 后，断线先补发 ticket，再重新 AuthReq。
- reconnect cursor：重连发送 `RoomReconnectReq.last_character_push_sequence`，值来自本地 `CharacterElementsCache.last_push_sequence`。
- redirect：收到服务端 redirect 后，客户端补发 ticket、连接新 endpoint、AuthReq 成功后发送 `RoomReconnectReq`，不发普通 `Authenticated` 进房事件。
- kick：收到 kick/revoke/duplicate login/ban/maintenance 等推送后，客户端清理连接和待处理 HTTP，请求层暴露 `AccountStatusChanged` 或 `GameAuthRejected`，不得自动用旧 ticket 重连。
- 维护模式：`MAINTENANCE`、`SERVER_MAINTENANCE` 或 HTTP 维护状态应显示为可诊断失败，保留 request id、HTTP status、error code 和 endpoint。

## 四属性验收

资料与快照：

1. 选角或 profile 返回中若带 `attributes`，客户端写入 `CharacterElementsCache`，但不把 profile 当作永久预测源。
2. 进入游戏后发送 `GetCharacterElementsReq(1413)`，收到 `GetCharacterElementsRes(1414)` 后刷新当前 `character_id` 的 `affinity`、`mastery` 和 `snapshot_refreshed_at`。
3. UI/调试面板展示地、火、水、风四属性时，以 `CharacterElementsCache` 当前快照为准。

push 与重连：

1. `CharacterElementsChangePush(1505)` 到达后，客户端只消费服务端 `after` 快照，更新 `last_push_sequence` 和 `last_push_revision`。
2. 过期、重复或乱序 push 的去重/保序由服务端和 reconnect cursor 共同兜底；客户端断线后必须重拉 `GetCharacterElementsReq`，不要本地永久累加 delta。
3. 断线重连成功后，客户端发送 `RoomReconnectReq.last_character_push_sequence`，随后发送 `GetCharacterElementsReq` 获取权威快照。
4. 道具、战斗、任务或场景临时效果造成的永久变化，客户端只能在响应或 push 到达后展示；临时 `effective_elements` 不写入永久 `affinity` / `mastery`。

## 日志与诊断字段

允许记录：

- HTTP: request id、operation、endpoint path、HTTP status、服务端 error code、状态转换。
- game proxy: connection id、seq、message type、endpoint、transport、错误码。
- session: account `player_id`、当前 `character_id`、`world_id`、状态机阶段。
- ticket: `ticket_fp`、payload fingerprint、过期时间、剩余秒数。
- reconnect: cause、redirect target、room id、rollout epoch、last push sequence。

禁止记录：

- access token、refresh token、game ticket 原文。
- 密码、Authorization header、Cookie、完整请求体中包含凭据的字段。
- 可复用的 ticket payload 原文或未脱敏 JWT。

脱敏规则：

- 凭据只记录短指纹，当前客户端使用 `DIAGNOSTIC_FINGERPRINT_LEN = 12` 的稳定短 fingerprint。
- 本地需要更密集的状态日志时设置 `MYSERVER_DIAGNOSTIC_TRACE=true`；线上默认保持 trace/debug 级别，不应把凭据相关字段提升到 info。
- 线上串联问题时按 request id、connection id、seq、endpoint、error code、ticket_fp、character_id、状态转换联合定位。

## 暂缓项

- 游客升级为正式账号。
- 登录态持久化和平台安全存储。
- Android 真机上的公网 DNS/TLS、网络切换、弱网领取对账、前后台恢复和系统返回键验收；由 07 清单单独执行和归档。
- KCP 应用层加密与更完整的抗攻击/限流策略；当前公网域名、TLS 证书、Caddy 边界和 `4000/UDP` KCP 入口已经完成准入。
- 完整属性面板、完整称号/职业 UI。
- 跨实例持久离线 push 补偿。
- 更完整的维护模式 UI、kick 原因本地化和多账号切换体验。
