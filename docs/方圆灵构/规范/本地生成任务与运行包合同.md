# 方圆灵构本地生成任务与运行包合同

## 文档定位

本文锁定本地 Codex 方圆内容创作的 v0 输入、run bundle 和 promotion 边界，供后续 `fangyuan_authoring` 开发工具实现。它不实现 CLI、不调用在线模型，也不替代现有 `catalog.rs`、`resolver.rs`、`blueprint.rs` 或 `audit.rs` 的校验。

蓝图字段仍以 [蓝图格式与生成约束](./蓝图格式与生成约束.md) 为准，catalog 的稳定 surface preset ID 和 noise suggestion 仍由 runtime resolver 解释，预算、finding 和审核结论仍以 [审核与预算规则](./审核与预算规则.md) 为准。本合同只定义后续工具如何把这些既有边界串成可审计的离线 authoring 过程。

v0 只支持一个对象的 simple blueprint。它只允许 cube 和 sphere，最多四种 surface preset；一个 preset 最多使用其 catalog 已登记的一条 noise suggestion，并且只通过 `surface_noise_enabled` 布尔值 opt-in。它不使用对象级 material binding table、任意 override、UV、tile index、noise 参数、Shader、脚本或游戏规则字段。

## 严格任务 Schema

机器可读的闭合字段定义位于 [本地生成任务.v1.schema.json](./本地生成任务.v1.schema.json)，离线有效样例位于 [本地生成任务.v1.fixture.json](./本地生成任务.v1.fixture.json)。后续 Rust CLI 必须按等价的严格结构解析，拒绝未知字段；不得依赖通用 JSON Schema 运行时作为游戏依赖。

任务根对象固定使用 `schema_version: "fangyuan-generation-task/v1"`，并包含以下字段：

| 字段 | v0 合同 |
| --- | --- |
| `task_id` | 本次创作任务的 kebab-case 标识；只用于 run 追踪，不决定正式资源名。 |
| `stable_id` | 小写 snake_case 正式资源标识；决定 promotion 目标文件名。 |
| `object_purpose` | 仅记录外观用途，例如 `scene_decoration` 或 `equipment_appearance`；不授权玩法强度。 |
| `prompt` | 单个对象的纯文本创作要求；不是命令、路径、凭据或 provider 调用载体。 |
| `budget` | `max_primitives`、`bounds`、单 primitive 和总 volume 上限；后续工具还必须与当前 blueprint/audit 硬限制比较。 |
| `allowed` | `primitive_kinds` 固定且顺序固定为 `cube`、`sphere`；`roles` 只能是现有 `FangyuanPrimitiveRole` 词表子集。 |
| `material_budget` | surface preset 和 material profile 的数量上限；preset 上限不得超过 `4`，每个 preset 只允许一条 catalog suggestion，且禁止任意 override。 |
| `forbidden_features` | 固定 v0 禁止项，防止 task 放宽路径、网络、Shader、UV、noise 或玩法边界。 |
| `additional_forbidden_features` | 可选的任务收紧项，例如禁止透明、发光或特殊表面；它只能收紧，不能解除固定禁止项。 |

`budget.max_primitive_volume` 不得高于 `budget.max_total_volume`。后续工具必须将 task 的数值视为对既有 `FangyuanBlueprint` 和 `FangyuanAuditBudgetProfile` 的额外收紧，不能通过 task 抬高 Rust 的硬上限。

`material_budget.max_surface_presets` 是对象内去重后的 preset 数量上限，范围为 `1..=4`；`material_budget.max_material_profiles` 是已有 material profile 的数量上限，范围为 `1..=8`。`allow_catalog_suggested_noise` 为 `true` 时，草稿仍只能对所选 preset 写 `surface_noise_enabled: true`，并由 resolver 使用该 preset 唯一已登记 suggestion；它不允许 task、草稿或 canonical 写入 noise tile、强度或其他参数。

任务 schema 不定义 provider、model、endpoint、token、账号、网络状态、本机路径或绝对时间字段。`prompt` 是描述性输入，不是执行脚本；任务作者不得把凭据、URL、文件路径或可执行内容藏在其中，后续 CLI 也不得将其解释为外部调用指令。

## Run Bundle

每次尝试均隔离在被 Git 忽略的目录：

```text
summary/fangyuan-generation/<run-id>/
  run-manifest.json
  input/task.source.json
  input/task.prepared.json
  input/catalog-context.json
  input/codex-task.md
  draft/blueprint.ron
  canonical/blueprint.ron
  audit/report.json
  promotion/decision.json
  logs/summary.json
```

所有 bundle 内路径是上表所列的固定、相对、ASCII 文件名。调用方提供的 `task_id`、`stable_id`、prompt 或任何模型输出都不能参与目录名或文件名拼接。每个文件的路径、字节长度和 SHA-256 都由 `run-manifest.json` 记录；hash 为其精确 UTF-8 文件字节的 64 个小写十六进制字符，不是模型声称的 hash。

| 文件 | schema version 或内容 | 用途 |
| --- | --- | --- |
| `run-manifest.json` | `fangyuan-generation-run/v1` | 记录 run ID、一次初始化时的本地工具时间、每个 artifact 的相对路径/字节数/hash 和 schema version。 |
| `input/task.source.json` | `fangyuan-generation-task/v1` | 经过严格 schema 验证的原始 task 复本；保留输入字节供追溯。 |
| `input/task.prepared.json` | `fangyuan-generation-prepared-task/v1` | 工具归一化 task 后的 JSON，并绑定 source task hash；不产生新的权限或放宽预算。 |
| `input/catalog-context.json` | `fangyuan-generation-catalog-context/v1` | 从既有 catalog validator/resolver 导出的受控 preset context、catalog identity 和 hash；不得包含图片像素、文件系统路径或 URL。 |
| `input/codex-task.md` | `fangyuan-generation-codex-task/v1` | 本地 Codex 的固定提示词协议，绑定 template version、prepared task hash 和 catalog context hash；只指定当前 run 的草稿写入边界。 |
| `draft/blueprint.ron` | 现有 `FangyuanBlueprint` RON v1 | 本地 Codex 或离线 fixture 给出的未批准草稿；其字节可变且不进入正式 assets。 |
| `canonical/blueprint.ron` | `FangyuanBlueprint` RON v1 的稳定写法 | 后续 canonical/有限修复后的候选，绑定 task、context 和 draft hash。 |
| `audit/report.json` | `fangyuan-generation-audit-report/v1` | 包装既有 Fangyuan audit result、修复动作、requested/resolved preset 和 canonical hash；不复刻 audit 规则。 |
| `promotion/decision.json` | `fangyuan-generation-promotion-decision/v1` | 纯决策记录，包含 canonical/context/audit hash、目标相对路径和目标旧 hash 预条件。 |
| `logs/summary.json` | `fangyuan-generation-log-summary/v1` | 有界的阶段、结果 code 和 artifact hash 摘要；不保存 token、原始 provider 响应、网络日志或绝对路径。 |

阶段 1 只定义这些输出，不要求它们已经由 CLI 生成。阶段 2 起的工具失败时必须保留已写入的输入和错误 report，但不得伪造 canonical、audit success 或 `ready_for_promotion` decision。

各 JSON wrapper 至少固定以下机器字段，且所有 hash 都是 64 个小写十六进制字符：

| Wrapper | 必填字段 |
| --- | --- |
| `run-manifest.json` | `schema_version`、`run_id`、`created_at_utc`、`time_source: "local_tool_clock"`、`codex_task_protocol{prompt_template_version, prepared_task_sha256, catalog_context_sha256, draft_sha256}` 和按固定路径排序的 `artifacts[{path, schema_version, bytes, sha256}]`。`draft_sha256` 在草稿不存在时为 `null`，由本地工具从精确草稿字节计算。 |
| `input/task.prepared.json` | `schema_version`、`source_task_sha256`、归一化后的 `task`；`task` 仍须满足 task v1，不能补充权限。 |
| `input/catalog-context.json` | `schema_version`、`prepared_task_sha256`、`catalog_content_sha256`、`catalog_dependency_sha256`、稳定排序的受控 `presets`。具体 preset 内容由阶段 3 复用 catalog validator/resolver 定义。 |
| `audit/report.json` | `schema_version`、`canonical_sha256`、`catalog_context_sha256`、`repair_actions`、既有 audit 的 `report`；没有 canonical 时只能写 failure report。 |
| `promotion/decision.json` | `schema_version`、`canonical_sha256`、`catalog_context_sha256`、`audit_sha256`、`target_relative_path`、`expected_target_sha256`、`status`。v0 status 只能是 `not_evaluated`、`blocked` 或 `ready_for_promotion`；实际写入结果属于后续 promotion report。 |
| `logs/summary.json` | `schema_version`、`run_id`、稳定排序的 `events[{stage, code, artifact_sha256}]`；不得包含原始 prompt、provider payload、token、网络数据或绝对路径。 |

`expected_target_sha256` 在目标不存在时为 `null`，否则必须等于 promotion 计算时读取的现有目标 hash。`target_relative_path` 固定为 `project/assets/fangyuan/blueprints/generated/<stable-id>.ron`，不能由外部输入覆盖。

## 本地 Codex 草稿协议

`prepare-task` 在当前 run 的 `input/codex-task.md` 写入固定的本地 Codex 提示词。该文件只允许模板插入 run ID、prepared task SHA-256 和 catalog context SHA-256；不包含 model、provider、endpoint、token、网络状态或模型可重复性声明。

Codex 必须严格依次读取相关设计文档、当前 run 的 `input/task.prepared.json` 和 `input/catalog-context.json`，不扫描无关仓库文件。它先在交互响应中给出对象计划和部件表，部件表至少包含 role、primitive 数量/比例、预算小计、surface preset 选择理由和 noise 决策；这些计划内容不写入草稿文件。

草稿只能写入当前 run 的 `draft/blueprint.ron`，且文件内容只能是一个 `FangyuanBlueprint` RON。primitive 仅可使用 cube/sphere、position、size、color、role，以及既有条件允许的 alpha、emissive、material profile、已登记 `surface_material_preset_id` 和布尔 `surface_noise_enabled`。可选 RON 字段使用 `Some(...)` 形式，例如 `surface_material_preset_id: Some("material:surface/x00/y00")`；未使用时省略。禁止路径、URL、UV、tile index、noise ID/strength/target、roughness、metallic、脚本、Shader、rotation、free mesh、对象级 material binding、lifecycle 和玩法字段。材质优先按部件复用，去重 surface preset 不得超过 task 上限且绝不超过 4；water/sky/lava 只有 task prompt 和部件 role 都明确要求时才可选择。

Codex 不能修改 promotion 目录、assets、catalog、文档、Rust 源码、task input、manifest、logs 或其他 run。草稿写入后由 `inspect-run` 重新读取文件并把精确 SHA-256 同步到 manifest 的 `codex_task_protocol.draft_sha256`；这一步只记录字节身份，不解析、canonical、审核或 promotion 草稿。

### Run ID、时间和版本

`run-id` 的格式固定为：

```text
fygen-v1-YYYYMMDDTHHMMSSZ-xxxxxxxxxxxx
```

前半部分由 run 初始化时本地工具的 UTC wall clock 格式化；后缀为本地生成并经目录冲突检查的 12 位小写十六进制 nonce。它不是 task hash、catalog hash、AI provider request ID 或模型版本。发生目录冲突时工具必须生成新的 nonce，不能复用或覆盖已有 run。

`run-manifest.json.created_at_utc` 只在 run 初始化时由本地工具 UTC wall clock 写入，使用 RFC 3339 的 `Z` 形式。其他诊断时间若以后需要，必须同样标明 `local_tool_clock` 来源。时间和 run ID 仅是追踪元数据，绝不进入 task、catalog context、canonical、audit 或 promotion 的内容 identity hash。

每个 JSON wrapper 都必须带自己的 schema version。JSON canonical 表示使用 UTF-8、无 BOM、LF 换行、稳定字段顺序和末尾单个换行；RON canonical 表示由后续 authoring 工具固定字段顺序、浮点格式、primitive 顺序策略和 LF 写出。原始 task 与 draft 保留原始字节，同时在 manifest 中记录其 hash。

## Promotion 目标和冲突策略

正式目标固定为：

```text
project/assets/fangyuan/blueprints/generated/<stable-id>.ron
```

`stable_id` 只能为 1 到 64 个小写 ASCII 字母、数字和下划线，并且首字符必须是字母。因此目标始终是单个 `.ron` 文件，不能携带子目录、扩展名、空格、drive、绝对路径或 URI。阶段 6 的 promotion 实现还必须再次通过 Fangyuan 首包路径校验。

默认策略是拒绝覆盖：目标不存在时才可写入；目标存在且与 canonical 的 SHA-256 相同，则视为幂等成功；目标存在但内容不同，则拒绝。后续显式更新必须提供与当前目标一致的 `expected_old_sha256`，并用临时文件加原子替换或等价安全写入。run bundle 中的 prompt、日志、草稿和 catalog context 永远不得复制到正式 assets。

## 确定性与非目标

同一 prompt 可以得到不同 AI 草稿，本合同不承诺模型输出可重复。确定性从已有 draft 字节开始：相同的 source/prepared task、catalog context、draft、canonical 规则和 audit policy 必须得到相同 canonical bytes、audit report 和 promotion decision bytes/hash。promotion decision 的目标旧 hash 预条件也是该稳定输入的一部分；目标状态改变时必须重新计算 decision，而不是复用旧结论。

本地 Codex 只能向当前 run 的 `draft/blueprint.ron` 写候选；它不能写 promotion 目录、catalog、Rust 源码、文档或其他 run。生产在线 provider、凭据、重试、限流、计费、内容安全和网络审计属于独立后续清单；不得在本地 authoring CLI 中预留 URL、token 或脚本入口。

后续 Shader、Bake 和游戏 runtime 只能消费已经 promotion 的 canonical blueprint 与现有 resolver/audit 结果，不能读取 prompt、draft 或 run logs。
