# 主世界 HUD 与场景内面板 清单

## 目标

为主世界提供 fixed host + approved `UiDocument` 的常驻 HUD，并以场景内面板形式接入设置、邮箱、家园和返回 Lobby。HUD 只在主世界网络与场景 ready 条件满足后显示，面板开关不应破坏当前 scene session 或误切换到 Lobby。

本清单负责 UI 宿主、动作、绑定、面板层级和交互生命周期；主世界房间与 Scene ready 由 `02_主世界进场与权威闭环清单.md` 负责，邮箱数据由 `05_邮箱界面与通知闭环清单.md` 负责。

Android 真机上的安全区、触控、系统返回键、前后台和公网业务验收集中转移至 `07_公网部署后Android真机验收清单.md`。本清单仍负责 Android 返回语义、响应式和输入合同的实现与自动化验证，不执行真机验收。

## 基础原则

- [x] 正式业务 View 使用 fixed host + approved `UiDocument`，Rust 只保留闭合 adapter、生命周期、场景和网络业务。（验证：`check-boundary` 将 `MainWorld` 列为 `game.main_world_hud` 正式业务 document route，所有门禁字段为 `true`）
- [x] HUD、Floating、Modal、Loading 和 Toast 使用 UI framework 的 owner/panel/layer 语义，不自行维护平行遮罩或焦点系统。（验证：`gameplay/host.rs` 的 HUD/Floating host 和 `close_top` 定向测试通过）
- [x] 场景内面板关闭后恢复主世界 HUD 和 gameplay 输入，不退出 scene session。（验证：`main_world_audio`、`main_world_mail` 与 `close_top` 定向测试通过）
- [x] 页面动作必须校验 document、owner、source node、参数和当前进场 generation。（验证：主世界 host allowlist、generation 和非法 source 拒绝定向测试通过）
