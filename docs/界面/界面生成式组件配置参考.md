# UI 生成式组件配置参考

本文面向生成式 UI、人工修订生成结果和声明式页面维护，集中说明 `UiDocument` 组件应如何配置，重点回答“某类组件需要哪些字段、怎样保持与 Rust 组件一致、出现偏差时检查哪里”。协议、安全预算和完整字段定义仍以 [界面声明式文档协议.md](界面声明式文档协议.md) 与 JSON Schema 为准。

当前可运行对照样例：

- Rust 代码版：`project/src/game/screens/dev/ui_gallery.rs`
- 生成式页面适配：`project/src/game/screens/dev/ui_document_gallery.rs`
- 确定性生成入口：`scripts/generate-ui-gallery-parity.ps1`
- 生成结果：`project/assets/ui/documents/approved/gallery/declarative_gallery.v1.json`
- Schema：`project/assets/ui/documents/schema/ui_document.v1.schema.json`

`declarative_gallery.v1.json` 是生成产物。长期配置应修改生成脚本并重新生成，不要只手工修改 JSON，否则下一次生成会覆盖改动。

## 1. 生成与修订顺序

1. 固定目标 viewport、device scale、window scale、locale 和页面状态。
2. 给参考页面中的每个区域建立稳定 node ID；需要逐项对照时使用相同语义的 pair ID。
3. 先确定 page、panel、section、Grid、card 和 frame 层级，再放文字、图片和控件。
4. 从主题语义确定文字 role、组件 variant 和状态，不凭截图为每个节点单独写颜色。
5. 为图片声明来源、尺寸、fit、焦点、裁切 frame 和失败行为。
6. 为控件声明 slot、状态、binding 和 action；业务动作必须由 Rust host 注册。
7. 通过 Schema、运行时校验、内容合同测试和固定尺寸截图后，才进入 approved 目录。

代码版和生成式版本应一一对应：

| 对照项 | 要求 |
| --- | --- |
| 页面标题 | 明确标注实现来源，例如 `UI 示例（Rust）`、`UI 示例（生成式）` |
| section | 标题、说明、组件组和顺序一致 |
| node ID | 使用稳定语义 ID，不使用随机 ID 或数组下标 |
| Grid | 列数、子项数量、gap、对齐方式一致 |
| card/frame | padding、gap、边框、圆角、裁切和尺寸约束一致 |
| 文案 | 复用相同 i18n key 和 fallback |
| 状态 | 按组件能力对应 normal 到 error 的状态矩阵 |
| 审计锚点 | 绑定到双方相同语义的标题或组件组 |

## 2. 通用节点

所有节点都需要唯一 `id`：

| `type` | 核心字段 | 用途 |
| --- | --- | --- |
| `container` | `layout`、`style`、`children`、可选 `repeat` | 页面、section、行列、Grid、card、frame |
| `text` | `content`、`typography`、`layout`、`style` | 标题、正文、caption、状态文案 |
| `image` | `asset`、`presentation`、`tint`、`placeholder`、`failure` | 普通图片和高级图片 |
| `icon` | `asset`、`tint`、`layout` | 非交互图标 |
| `spacer` | `layout` | 显式占位，不用于掩盖错误布局 |
| 控件节点 | `component`、值字段、action、`layout`、`style` | 映射 framework widgets |

可见文案优先使用 i18n：

```json
{
  "type": "text",
  "id": "profile.section.title",
  "content": {
    "i18n_key": "profile.section.title",
    "fallback": "Profile"
  },
  "style": {
    "text_role": "section_label",
    "role": "muted"
  }
}
```

只有诊断值或测试 fixture 才使用 `literal`。生成器不应为同一可见文案创建另一套 i18n key。

## 3. 布局配置

### 3.1 常用 layout 字段

| 字段 | 说明 | 配置原则 |
| --- | --- | --- |
| `display` | `flex`、`grid`、`none` | 固定列布局显式使用 `grid` |
| `width` / `height` | `px`、`percent`、`auto` 等 | 固定格式组件至少约束一个轴或宽高比 |
| `min_*` / `max_*` | 尺寸边界 | 防止文案、状态或加载结果改变整体尺寸 |
| `aspect_ratio` | 宽高比 | 缩略图、头像和预览 frame 优先使用 |
| `margin` / `padding` / `border` | 盒模型 | padding 属于 layout；颜色和圆角属于 style |
| `gap` | Flex 默认间距 | Grid 推荐显式 `row_gap` / `column_gap` |
| `direction` / `wrap` | Flex 方向和换行 | 不用于替代固定列 Grid |
| `align_*` / `justify_*` | 对齐方式 | Grid card 通常 center + stretch |
| `overflow` | visible、clip、scroll | 图片圆角裁切在 frame 上使用 clip |
| `grid_columns` / `grid_rows` | Grid track | 固定对照必须明确列数 |

不要按 viewport 宽度连续缩放字号。响应式变化应切换列数、方向、padding 或可见内容，文字仍使用主题 role。

### 3.2 固定列 Grid

当前 Gallery 三列 Grid 的标准结构：

```json
{
  "type": "container",
  "id": "gallery.section.image_tiling",
  "layout": {
    "display": "grid",
    "width": { "percent": 100 },
    "grid_columns": [
      { "repeat": 3, "size": { "fr": 1.0 } }
    ],
    "grid_auto_rows": ["auto"],
    "row_gap": { "px": 12 },
    "column_gap": { "px": 12 },
    "align_items": "center",
    "justify_items": "stretch"
  },
  "children": []
}
```

固定参考图对照中不要：

- 用 `direction: row` + `wrap: wrap` 代替明确列数。
- 只给子项固定宽度而不声明 Grid track。
- 为较高 card 单独增加 margin，破坏同一行对齐。
- 遗漏子项 `width: 100%`，让内容决定卡片宽度。

响应式列数通过 `responsive[].overrides` 修改 Grid layout，不复制整组 children。

### 3.3 Panel、card 和 frame

| 结构 | 职责 |
| --- | --- |
| Panel | 包围完整 section，提供最大宽度、panel padding、背景和边框 |
| Card | 包围一个重复项目，统一内边距、标签间距、背景和边框 |
| Frame | 提供图片或 clip 文本的稳定尺寸、宽高比和裁切边界 |

Gallery 图片 card 与 Rust 版一致的当前值：

```json
{
  "type": "container",
  "id": "sample.card",
  "layout": {
    "width": { "percent": 100 },
    "direction": "column",
    "gap": { "px": 3 },
    "padding": { "all": { "px": 6 } },
    "overflow": { "x": "clip", "y": "clip" }
  },
  "style": { "component": "gallery_image_card" },
  "children": []
}
```

这里的 card padding 对应当前 `theme.layout.row_gap`，内部 gap 使用其一半。其他页面应先查目标主题和 Rust helper，不应把 Gallery 数值当成全局常量。

方形图片 frame：

```json
{
  "type": "container",
  "id": "sample.frame",
  "layout": {
    "width": { "percent": 100 },
    "height": "auto",
    "aspect_ratio": 1.0,
    "overflow": { "x": "clip", "y": "clip" }
  },
  "style": { "component": "gallery_image_frame" },
  "children": []
}
```

图片 fixture、正式缩略图和圆角图片都应使用“card -> frame -> image”结构。只给 image 设置宽高不会自动得到卡片边框或圆角裁切。

## 4. 文字和截断

### 4.1 文字角色

`style.text_role` 决定字号/字重语义，`style.role` 决定颜色语义：

| 用途 | `text_role` | `role` |
| --- | --- | --- |
| 页面主标题 | `title` | primary 或省略 |
| section 标题 | `section_label` | `muted` |
| 副标题 | `subtitle` | muted 或 primary |
| 正文 | `body` | primary |
| 说明、图片标签 | `caption` | `muted` |
| 按钮文字 | `button` | 由组件视觉决定 |
| 错误说明 | `caption` | `error` |

“颜色深浅不一致”通常是遗漏了 `role: muted`。先核对文字语义，再考虑显式颜色。

`typography` 可配置 `font_role`、`weight`、`line_height`、`alignment`、`wrap`、`max_lines` 和 `overflow`。wrap 支持 `word`、`character`、`word_or_character`、`no_wrap`；overflow 支持 `visible`、`clip`、`ellipsis`。Regular、Medium、Bold 使用 `weight`，不能用颜色模拟字重。

### 4.2 Clip 和 ellipsis

`clip` 必须由固定父 frame 执行：

```json
{
  "type": "container",
  "id": "message.clip.frame",
  "layout": {
    "width": { "px": 280 },
    "height": { "px": 32 },
    "overflow": { "x": "clip", "y": "clip" }
  },
  "children": [
    {
      "type": "text",
      "id": "message.clip",
      "content": { "literal": "Long text" },
      "typography": { "wrap": "no_wrap", "overflow": "clip" },
      "style": { "text_role": "body" }
    }
  ]
}
```

单行 ellipsis 至少声明 `wrap: no_wrap`、`max_lines: 1`、`overflow: ellipsis`，并提供有限宽度。没有边界时不存在可计算的截断位置。

## 5. component 通用配置

| 字段 | 内容 | 说明 |
| --- | --- | --- |
| `variant` | default、primary、secondary、destructive、subtle、outline、info、success、warning、error | framework presentation preset |
| `size` | small、medium、large | 补充未显式声明的默认尺寸，不覆盖权威 layout |
| `states` | 状态数组 | 静态 fixture 或 binding 状态；默认 normal |
| `state_overrides` | 状态到 `UiStyle` 的映射 | 只覆盖该状态变化的视觉字段 |
| `slots` | 类型化 slot map | label、图标、placeholder、helper、error 等 |
| `children` | 受限子节点 | 当前仅 Scroll 和单目标 Tooltip 支持特定嵌套 |
| `bindings` | disabled、loading、selected、value、variant | 不能指向任意 ECS 属性 |

状态优先级：

```text
disabled > loading > error > pressed > hovered > selected > focused > empty > normal
```

声明多个状态不会叠加所有视觉，而是解析一个 effective state。

组件支持的状态：

| 组件 | 支持状态 |
| --- | --- |
| Button / ImageButton / Tab | normal、hovered、pressed、focused、selected、disabled、loading |
| TextInput | normal、hovered、pressed、focused、disabled、empty、error |
| Badge | normal、selected、disabled、loading、empty、error |
| Progress | normal、disabled、loading、empty、error |
| Tooltip | normal、disabled、error |
| Select / Dropdown | 全部九种状态 |
| Checkbox / Toggle / Segmented | 除 empty 外的状态 |
| Slider / Stepper | normal、hovered、pressed、focused、disabled、error |
| Scroll / Modal | normal、loading、empty、error |

不支持的状态会在文档校验阶段被拒绝，不会静默降级成 normal。

### 5.1 slot 支持矩阵

| 控件 | 允许的 slot |
| --- | --- |
| Button | label、leading、trailing |
| ImageButton | label |
| TextInput | label、placeholder、helper、error |
| Checkbox / Toggle | label |
| Segmented / Slider / Stepper | label、helper、error |
| Scroll | empty、error |
| Modal | title、body、error |
| Badge / Progress | label |
| Tab | label、leading |
| Tooltip | body |
| Select | label、placeholder、empty、error |

未知 slot 会被校验器拒绝。不要把 framework 控件的内部 Text、mark、thumb 或 indicator 结构复制进 document。

## 6. 组件细节

### 6.1 Button

```json
{
  "type": "button",
  "id": "profile.save",
  "component": {
    "variant": "primary",
    "size": "medium",
    "slots": {
      "label": {
        "kind": "text",
        "content": { "i18n_key": "profile.save", "fallback": "Save" }
      }
    }
  },
  "on_click": { "action": "profile.save" }
}
```

- 普通业务动作使用 `on_click`，不要用图片或 Text 假装按钮。
- leading/trailing 可使用 icon 或 image，资源必须先在 `assets` 声明。
- 固定按钮行约束高度和最小宽度，loading/selected 不得改变尺寸。
- variant 只提供 preset；节点显式 layout 和解析后的 style 仍是权威配置。

### 6.2 ImageButton 和 Icon

`image_button` 需要 `asset`、`presentation`、可选 `tint`、component label 和 `on_click`。纯图标按钮也必须提供 label 作为可访问名称。单色可染色图标与全彩图标应遵守资源 tint policy，不要用文本字符、emoji 或手写问号替代正式图标。

固定图标按钮应约束点击区域，例如 46 x 46；图片自身尺寸不能替代触控区域。非交互装饰才使用 `icon` 节点。

### 6.3 TextInput

```json
{
  "type": "text_input",
  "id": "profile.player_name",
  "value": "Pilot 01",
  "max_chars": 64,
  "readonly": false,
  "component": {
    "slots": {
      "label": {
        "kind": "text",
        "content": { "literal": "Player name" }
      },
      "placeholder": {
        "kind": "text",
        "content": { "literal": "Player name" }
      },
      "helper": {
        "kind": "text",
        "content": { "literal": "Shown to other players." }
      }
    }
  },
  "on_change": { "action": "profile.changed" },
  "on_submit": { "action": "profile.submit" }
}
```

- `max_chars` 必须在 `1..=4096`；敏感输入使用 `security: sensitive`。
- `readonly` 是节点字段；disabled、loading、error 使用 state 或 binding。
- label 是控件语义信息，当前不参与输入框内部布局；需要可见字段标题时放独立 Text。
- helper 和 error 显示在框体下方；error state 显示 error slot 和主题错误边框。
- placeholder、value、helper、error 不应挤在框体内部。
- 连续字段放在显式 column 中。当前 Gallery 使用 6px 字段间距，输入框运行时为框外消息预留空间。

错误态 component：

```json
{
  "states": ["error"],
  "slots": {
    "placeholder": {
      "kind": "text",
      "content": { "literal": "Required" }
    },
    "error": {
      "kind": "text",
      "content": { "literal": "This field is required." }
    }
  }
}
```

### 6.4 选择控件

| 类型 | 值字段 | 选项 | action |
| --- | --- | --- | --- |
| checkbox | `checked: bool` | 无 | `on_change` |
| toggle | `on: bool` | 无 | `on_change` |
| segmented | `selected: string?` | `options[]` | `on_change` |

Segmented option 使用稳定 value 和本地化 label。不要从显示文案推导业务值，也不要用 `[x]`、`ON/OFF` 文本模拟正式控件。

### 6.5 Slider、Stepper、Progress

| 类型 | 数值字段 | 注意事项 |
| --- | --- | --- |
| slider | value、min、max | 浮点值，持续变化通过 `on_change` |
| stepper | value、min、max、step | 整数步进，step 必须有效 |
| progress | value | 只展示；loading/empty/error 使用状态 |

数值控件的 label/helper/error 使用 slots。不要用静态 Text 替代当前值，也不要让文本长度改变轨道或步进按钮尺寸。

### 6.6 Badge、Tab、Select、Tooltip

| 类型 | 必需配置 | 关键限制 |
| --- | --- | --- |
| badge | label slot | 只展示状态，不承担点击动作 |
| tab | value、label，可选 leading、on_change | 使用稳定 value 区分 |
| select | options、可选 selected、placeholder、on_change | option value 唯一；覆盖层由 framework 管理 |
| tooltip | body、恰好一个 component child | 不应被普通滚动 frame 裁切 |

Select 和 Tooltip 的弹出层、边缘避让、Escape、click-away 和 owner cleanup 由 Panel Manager 处理。文档不设置内部弹层坐标。

### 6.7 Scroll 和 Modal

- Scroll 使用 `component.children`，可配置 `row_gap`、`max_height`、`block_lower`，empty/error slot 表示列表状态。
- Modal 使用 title/body/error slot 和 `cancellable`，页面只触发已注册动作。
- 普通 container 不应通过高 `z_index` 模拟 Modal；输入阻断、焦点和关闭语义必须经过 Panel Manager。

## 7. 图片配置

### 7.1 普通 fit

```json
{
  "type": "image",
  "id": "profile.avatar",
  "asset": "profile_avatar",
  "presentation": {
    "kind": "fit",
    "fit": "cover",
    "focus": { "x": 0.5, "y": 0.35 }
  },
  "layout": {
    "width": { "percent": 100 },
    "height": { "percent": 100 }
  }
}
```

| fit | 行为 | 常见用途 |
| --- | --- | --- |
| natural | 按源图自然尺寸 | 原始预览 |
| stretch | 独立拉伸两个轴 | 可变形 fixture、纯装饰面 |
| contain | 完整显示并留空 | 图标、商品、需看全貌的内容 |
| cover | 填满并裁切 | 头像、封面；必须检查 focus |

focus 是源图左上角归一化坐标，运行时 clamp 到 `0..=1`。Cover 必须检查横竖 frame 和焦点两端。

### 7.2 Nine-slice

```json
{
  "kind": "nine_slice",
  "insets": { "left": 12, "right": 12, "top": 12, "bottom": 12 },
  "center": { "kind": "stretch" },
  "sides": { "kind": "stretch" },
  "max_corner_scale": 1.0,
  "max_generated_slices": 256
}
```

Nine-slice 只适合边角和边线可独立缩放的素材。至少验证主 panel 和小/中/大尺寸。

### 7.3 Bounded tiling

```json
{
  "kind": "tiled",
  "axis": "both",
  "stretch_value": 0.5,
  "max_repeats": 32
}
```

axis 是 x、y 或 both。平铺必须设置有限 frame 和预算；三种模式分别建立 card。不要让图片自然尺寸决定 Grid 行高，也不要遗漏 card 外框。

### 7.4 Atlas frame

```json
{
  "kind": "atlas_frame",
  "frame": "red_circle",
  "fit": "stretch"
}
```

frame 名称必须存在于 asset 的 `frames` 中。asset 还需要权威源尺寸和 frame rect；运行时拒绝越界、源尺寸不一致以及 atlas 与 slice/tile 的非法组合。

高级图片必须声明可验证的源尺寸和 decoded bytes。失败占位不应改变 frame 尺寸，页面也不应自行计算 `ImageNode.rect`。

## 8. 样式、token 和状态覆盖

优先在 document 顶层定义 token 和复用 style：

```json
{
  "tokens": {
    "panel_surface": { "kind": "color", "value": "#1a2129f0" },
    "panel_border": { "kind": "color", "value": "#38474fff" }
  },
  "styles": {
    "content_panel": {
      "properties": {
        "background": {
          "kind": "solid",
          "color": { "kind": "token", "token": "panel_surface" }
        },
        "border": {
          "width": { "kind": "literal", "value": 1.0 },
          "color": { "kind": "token", "token": "panel_border" }
        }
      }
    }
  }
}
```

样式解析顺序：

```text
token -> component style / extends -> node style.inline -> current state override
```

后层只覆盖明确变化的字段。文字颜色、字体、字号、行高、字距和字重按子字段合并；背景、边框、圆角、阴影和材质按完整属性覆盖。不要依靠 JSON object key 顺序。

颜色处理顺序：先选正确主题 role/style component，再确认状态，最后才新增 token/style。不要为多个相同 card 复制相同 inline background/border。

## 9. Binding 和 action

Component binding 只允许 disabled、loading、selected、value、variant：

```json
{
  "bindings": {
    "value": {
      "binding_path": "profile.player_name",
      "direction": "two_way"
    },
    "disabled": "profile.readonly"
  }
}
```

- 类型必须与 binding declaration 一致。
- `on_click`、`on_change`、`on_submit` 只引用 Rust host 已注册 action ID。
- 文档不能写 Rust 函数名、system 名、网络地址或脚本。
- 传递当前控件值时使用协议的 current control value 参数，不读取内部实体。

## 10. 响应式配置

响应式 variant 只覆盖变化字段：

```json
{
  "id": "compact_portrait",
  "when": {
    "width_class": "compact",
    "orientation": "portrait"
  },
  "overrides": [
    {
      "node_id": "profile.page",
      "set": {
        "layout": {
          "padding": { "all": { "px": 14 } },
          "gap": { "px": 10 }
        }
      }
    }
  ]
}
```

推荐调整 Grid 列数、Flex 方向、page/panel padding、gap、最大宽度、安全区和非关键装饰可见性。不要复制整个页面，也不要按 viewport 宽度缩放字体。

## 11. 常见问题定位

| 现象 | 优先检查 |
| --- | --- |
| 字体大小或颜色深浅不同 | text_role、muted/error role、weight、i18n 文案 |
| 固定列区域错位 | 是否误用 wrap；Grid repeat、gap、子项 width |
| 第二行图片没有方框 | 是否缺少 card；frame 是否直接放进 Grid |
| 两张图片尺寸不同 | frame 的宽高/比例；image 是否 100% x 100% |
| Bounded tiling 行高异常 | card padding/gap、有限 frame、Grid 对齐 |
| 圆角没有裁切 | radius 是否在 frame；overflow 是否 clip |
| Clip/Ellipsis 未生效 | 是否有有限边界、no-wrap、max_lines |
| 问号或图标异常 | 是否使用正式 icon asset 和 tint policy |
| 输入框文字挤在框内 | label/helper/error slot；是否绕过正式 runtime |
| 输入框无错误边框 | 是否进入 error state；error slot 是否存在 |
| disabled/error 冲突 | 状态优先级和 binding snapshot |
| 同专题截图上下错位 | 双方审计锚点是否绑定同一语义节点 |
| 手工修复下次消失 | 是否只改生成 JSON，没有改生成器/source task |
