# UI 3D 预览能力

本文记录 `framework/ui/preview3d/` 这一通用能力的定位、边界、公共 API、内部职责、生命周期和典型用法。它描述当前设计而不是开发任务清单；实现步骤见 `summary/界面3D预览通用能力_checklist.md`。

## 1. 设计目标

为道具预览、家园预览、装备 3D 展示、角色卡 3D 头图等场景提供**统一的"在 UI 面板里渲染一段 3D 内容"**能力。多个页面和多个 AppUiMode 共享同一份实现，避免每处都从相机、RenderTarget、RenderLayers、Image 资源这一层手动接线。

设计目标：

- **业务层只调高层 API**：不直接接触 `Camera3d`、`RenderTarget::Image`、`RenderLayers`、`Assets<Image>`，全部封装在 framework 内。
- **不污染现有渲染分层**：UI 全局相机（`IsDefaultUiCamera`、`GLOBAL_UI_CAMERA_ORDER`）契约零变更；3D 预览通过 Image 通道注入到 UI 节点。
- **不污染场景框架**：投影相机不进 `SceneCameraRig`、不挂 `SceneOwned`，与 `ScenePlugin` 的清理链路独立。
- **多实例并存**：同一画面可以有多张 3D 预览，每张有独立的 Image handle、相机、RenderLayers。
- **生命周期自动收敛**：业务侧 despawn UI 节点时，相机、内容实体、Image 资源自动清理，无需手动 unregister。
- **可观测、可测试**：每一个 viewport 有稳定 session id，可独立定位和单元测试。

非目标：

- 不替代 `framework/scene/` 的场景相机（主世界 / Home / Arena 相机仍由 ScenePlugin 管理）。
- 不提供正式后处理 / bloom / vignette 等屏幕空间效果（属于 Render/VFX 系统，本期未实现）。
- 不参与 authority / replay / network / MyServer 任何同步链路。
- 不改 `UiDocument` runtime schema（仍是 2D 节点，3D 内容以 Image 形式喂给 ImageNode）。

## 2. 模块位置

```
project/src/framework/ui/preview3d/    ← 本能力
```

与 `framework/ui/widgets/`、`overlays/`、`document/`、`audit/` 平行，挂在 `framework/ui/mod.rs` 下，由 `UiFrameworkPlugin` 注册。

| 候选位置 | 是否合适 | 原因 |
| --- | --- | --- |
| `framework/ui/preview3d/` | ✅ 选定 | 入口始终是 UI panel；消费方是 UI framework；和 widgets/overlays/document 同层 |
| `framework/scene/preview3d/` | ❌ | 子相机是实现细节，不属于场景相机栈；放在这里会让 scene framework 重新学习"有独立清理的相机" |
| `framework/render/preview3d/` | ❌ | 项目尚未抽象独立的 render framework；不要过早分层 |
| `game/features/projection_3d_to_ui/` | ❌ | 会绑定到具体 AppUiMode 或玩法；多业务复用需要重新打包 |

## 3. 目录结构

```
project/src/framework/ui/preview3d/
├── mod.rs          # 公共 API：Preview3dViewportPlugin + 公开函数 + re-exports
├── config.rs       # Preview3dConfig / PreviewContent / PreviewCameraConfig / PreviewStyle / PreviewFit / PreviewPixelScale
├── viewport.rs     # Preview3dViewport 组件 + Preview3dOwned 清理 marker + Preview3dSessionId + RemovedComponents 观察者
├── camera.rs       # 投影相机实体 spawn / Transform 应用 / RenderLayers 分配
├── target.rs       # Image 资源创建 / device-scale 物理像素计算 / 复用 / resize
└── widget.rs       # UI 侧 bundle（Node + ImageNode + 圆角 + clip）+ 挂载 helper
```

文件职责：

| 文件 | 唯一允许直接接触的 Bevy 类型 |
| --- | --- |
| `target.rs` | `Assets<Image>`、`Image::new_target_texture`、`Handle<Image>`、`TextureUsages` |
| `camera.rs` | `Camera3d`、`Camera`、`Projection`、`RenderLayers`、`Transform` |
| `viewport.rs` | `Component` marker、`Observer` / `RemovedComponents`、`Entity` |
| `widget.rs` | `Node`、`ImageNode`、`NodeImageMode`、`BorderRadius`、`Overflow` |
| `config.rs` | 无（纯数据结构 + `validate()`） |
| `mod.rs` | 无（组合 re-export + Plugin 注册） |

`Assets<Mesh>`、`Assets<StandardMaterial>` 等业务侧资源由业务系统在 `PreviewContent::Spawn` 闭包里直接访问，不属于本能力。

## 4. 公共 API

### 4.1 配置类型（`config.rs`）

```rust
pub struct Preview3dConfig {
    pub logical_size: Vec2,             // UI 上的逻辑像素大小（dp/px）
    pub camera: PreviewCameraConfig,    // 投影相机配置
    pub content: PreviewContent,        // 要渲染的内容来源
    pub fit: PreviewFit,                // ImageNode 缩放模式
    pub style: PreviewStyle,            // 圆角/背景/边框
    pub pixel_scale: PreviewPixelScale, // 物理像素策略
}

pub enum PreviewContent {
    None,                               // 业务后续用 add_preview3d_content 加
    TagEntities(Vec<Entity>),           // 给已有 entity 加 RenderLayers
    Spawn(PreviewContentSpawner),       // 闭包形式，框架负责 session root
}

pub struct PreviewCameraConfig {
    pub layer: RenderLayers,            // 强制独占 layer，业务只能请求，框架分配
    pub projection: Projection,
    pub initial_transform: Transform,
    pub clear_color: Color,
    pub field_of_view: Option<f32>,
}

pub enum PreviewFit { Stretch, Contain, Cover { focus: Vec2 } }
pub enum PreviewPixelScale {
    Logical,
    DeviceScale(f32),
    FixedPhysical { width: u32, height: u32 },
}
pub struct PreviewStyle {
    pub corner_radius: f32,
    pub background: Option<Color>,
    pub border: Option<UiRect>,
}
```

`Preview3dConfig::validate()` 负责检查 logical_size > 0、camera layer 合法、pixel_scale 有限值；`spawn_preview3d_viewport` 在调用前会再走一次。

### 4.2 组件与函数（`mod.rs` 暴露）

```rust
#[derive(Component)]
pub struct Preview3dViewport {
    pub session_id: Preview3dSessionId,
    pub image: Handle<Image>,
    pub camera: Entity,
    pub logical_size: Vec2,
    pub layer: RenderLayers,
}

/// 在 parent 下生成一个完整的 3D 预览 UI 节点。返回 UI 实体 id。
pub fn spawn_preview3d_viewport(
    commands: &mut Commands,
    images: &mut Assets<Image>,
    parent: Entity,
    config: Preview3dConfig,
) -> Entity;

/// 调整投影相机 Transform（orbit / spin / 程序化动画都用这个）。
pub fn set_preview3d_camera_transform(
    viewport_entity: Entity,
    transform: Transform,
    cameras: &mut Query<&mut Transform, With<Preview3dProjectionCamera>>,
);

/// 把已有 entity 纳入这个 viewport 的渲染集合（自动加 RenderLayers）。
pub fn add_preview3d_content(
    viewport_entity: Entity,
    entity: Entity,
    commands: &mut Commands,
);

/// 业务侧主动 despawn；通常直接 DespawnRecursive UI 节点即可，observer 会兜底。
pub fn despawn_preview3d_viewport(commands: &mut Commands, viewport_entity: Entity);
```

业务层只需要 `spawn_preview3d_viewport` + 可选的 `set_preview3d_camera_transform` + `add_preview3d_content` 三件套，其余 API 都是工具性辅助。

## 5. 内部实现要点

### 5.1 target.rs — 图像资源

- 唯一允许直接操作 `Assets<Image>` 的文件。
- `create_preview_image(logical_size, device_scale, pixel_scale) -> Handle<Image>`：根据 `PreviewPixelScale` 计算物理像素尺寸，调用 `Image::new_target_texture` 生成 RenderTarget Image，并把 `TextureUsages::TEXTURE_BINDING` 置位确保可采样。
- `resize_preview_image(handle, new_logical_size, device_scale, images)`：recreate Image 并替换 handle；同步更新 `PreviewImageRegistry`。
- `PreviewImageRegistry` 是普通 resource，结构为 `HashMap<Preview3dSessionId, (Handle<Image>, UVec2)>`，供 resize 和 observer 清理使用。
- device scale 来自 `framework/ui/core/viewport.rs::UiViewport`，不要重新计算。

### 5.2 camera.rs — 投影相机

- 唯一允许直接操作 `Camera3d / Camera / Projection / RenderLayers / Transform` 的文件。
- `spawn_projection_camera(session_id, config) -> Entity`：order = `-2`（低于 `SCENE_CAMERA_3D_ORDER = -1`），不挂 `IsDefaultUiCamera`，不挂 `SceneOwned`，带 `Preview3dProjectionCamera` 私有 marker。
- `apply_camera_transform(camera_entity, transform)`：单纯改 Transform，不动 `Camera::order` 或 `RenderTarget`。
- RenderLayers 分配：内部维护 `Preview3dLayerAllocator`，从 layer `24` 起单调递增（避让 0/1-15 这些 scene camera 常用区间），分配后写入 component；业务层传入的 `RenderLayers::from_layers(&[N])` 中 `N` 仍可读，但 framework 会替换为实际分配值并写回 `Preview3dViewport.layer`。
- 多个 viewport 共存时，layer 必须互不重叠；分配器在分配前查冲突并返回错误。

### 5.3 viewport.rs — 生命周期

- `Preview3dSessionId` 是 `u64`，由 `Preview3dSessionCounter` resource 单调递增分配，保证多 viewport 隔离和清理无遗漏。
- `Preview3dOwned(session_id)` marker 同时挂在：投影相机实体、内容实体根节点（如果用 Spawner 模式）、任何 `add_preview3d_content` 后追加的 entity。
- 通过 `RemovedComponents<Preview3dViewport>` observer 监听 UI 节点销毁，触发清理：
  1. `DespawnAllWith<Preview3dOwned>` 过滤 `session_id`，回收相机和内容。
  2. `assets_images.remove(&handle)` 回收 Image 资源。
  3. 从 `PreviewImageRegistry` 和 `Preview3dLayerAllocator` 中移除 entry。
- 顺序：清理顺序不依赖具体调度；observer 在 UI 节点 despawn 触发时立即同步执行（`Observer` 在 Bevy 0.18 中支持同步触发）。

### 5.4 widget.rs — UI 集成

- `preview3d_viewport_bundle(image_handle, fit, style) -> (Node, ImageNode, BackgroundColor, Name)` 元组，让业务层用 `parent.spawn(...)` 挂上。
- 强制 `overflow: Overflow::clip()`、`border_radius` 来自 `PreviewStyle`。
- 复用 `framework/ui/widgets/image.rs` 的 `UiImageFit` → `NodeImageMode` 映射，不另搞一套 fit 类型。
- 不挂 `UiPanelRoot` / `UiLayerRoot`：预览属于业务 panel 的子节点，宿主身份由父节点决定。

### 5.5 config.rs — 纯类型

- 不依赖任何 bevy 系统或 plugin。
- `Preview3dConfig::validate()` 走 pure check：logical_size 各分量 > 0、camera layer 数组非空、pixel_scale 有限值。
- `PreviewContent::Spawn` 用 `Box<dyn FnOnce(&mut ChildBuilder, &mut Commands, …)>` 形式；闭包参数由 framework 注入已挂好 `Preview3dOwned(session_id)` marker 的 parent ChildBuilder，避免业务层重复挂 marker。

## 6. 生命周期模式

业务层可选三种使用方式之一，框架统一支持：

| 模式 | 用法 | 适用场景 |
| --- | --- | --- |
| **节点级联** | UI 节点 despawn 时自动触发 observer 清理相机/内容/Image | 大多数 panel 关闭路径 |
| **State-bound** | 给 UI 节点加 `DespawnOnExit(AppUiMode::X)` | AppUiMode 切换驱动 |
| **手动** | 调用 `despawn_preview3d_viewport(commands, entity)` | 复杂状态机、池化复用 |

三种模式底层都收敛到 `Preview3dOwned(session_id)` + observer，业务层可混用。

## 7. 业务使用示例

```rust
// 道具卡片 viewport
fn spawn_item_preview(
    mut commands: Commands,
    mut images: ResMut<Assets<Image>>,
) {
    let viewport = preview3d::spawn_preview3d_viewport(
        &mut commands,
        &mut images,
        item_card_panel,
        Preview3dConfig {
            logical_size: vec2(360.0, 480.0),
            camera: PreviewCameraConfig {
                layer: RenderLayers::from_layers(&[preview3d::allocate_layer()]),
                projection: Projection::Perspective(PerspectiveProjection {
                    fov: 35.0_f32.to_radians(),
                    ..default()
                }),
                initial_transform: Transform::from_xyz(0.0, 0.6, 1.8)
                    .looking_at(Vec3::new(0.0, 0.5, 0.0), Vec3::Y),
                clear_color: Color::NONE,
                field_of_view: Some(35.0_f32.to_radians()),
            },
            content: PreviewContent::Spawn(Box::new(|parent, _commands, _meshes, _materials| {
                parent.spawn((
                    PbrBundle {
                        mesh: item_mesh(),
                        material: item_material(),
                        transform: Transform::from_xyz(0.0, 0.5, 0.0),
                        ..default()
                    },
                    Preview3dContentMarker,
                ));
                parent.spawn((
                    DirectionalLightBundle {
                        directional_light: DirectionalLight {
                            color: Color::WHITE,
                            illuminance: 8000.0,
                            shadows_enabled: true,
                            ..default()
                        },
                        transform: Transform::from_xyz(2.0, 4.0, 2.0)
                            .looking_at(Vec3::ZERO, Vec3::Y),
                        ..default()
                    },
                    Preview3dContentMarker,
                ));
            })),
            fit: PreviewFit::Contain,
            style: PreviewStyle {
                corner_radius: 16.0,
                background: Some(Color::srgba(0.05, 0.05, 0.07, 1.0)),
                border: None,
            },
            pixel_scale: PreviewPixelScale::DeviceScale(1.0),
        },
    );

    // 后续相机摆动
    // set_preview3d_camera_transform(viewport, new_transform, &mut cameras);
}

// 家园预览 viewport：同样的 spawn_preview3d_viewport 调用，只换 config
```

## 8. 边界保证

| 现有约束 | 满足方式 |
| --- | --- |
| 不创建第二个 3D Camera（game layer 范围内） | 投影相机由 framework/ui/preview3d 自管理，属于 framework 层扩展 |
| 不直接写 `Camera` / `Projection` / `Transform` 在 game layer 业务系统 | 业务层只调 `spawn_preview3d_viewport` / `set_preview3d_camera_transform` |
| UI 全局相机独立，不把 HUD 纳入场景相机栈 | UI 相机 0 改动，3D 通过 Image 通道注入 |
| 不改变 `SceneOwned` / `SceneCameraRig` 语义 | 投影相机不挂 `SceneOwned`，自有 `Preview3dOwned` 清理链路 |
| 不改变 authority / replay / network / MyServer 语义 | 纯渲染层，0 状态依赖 |
| RenderLayers 不与场景主相机冲突 | 投影相机独占 layer 24+，由 `Preview3dLayerAllocator` 去重 |
| Bevy `RenderTarget::Image` 用法与 `RenderTarget::Window` 同源 | `target.rs` 使用 `RenderTarget::Image(ImageRenderTarget { handle, scale })` |
| 复用现有 `UiViewport` / `UiImageFit` | `target.rs` 直接读 `UiViewport`，`widget.rs` 复用 `UiImageFit` 到 `NodeImageMode` 映射 |
| `cargo check` / 测试 / `cargo fmt` 不退化 | 每个阶段独立验证（见配套 checklist） |

## 9. 已知限制与未来工作

当前实现**不包含**：

- 相机 shake / FOV kick / transform tween / 多相机 profile（属于场景相机系统，见 `docs/场景/摄像机管理系统设计.md`）。
- 屏幕空间后处理（bloom / vignette / motion blur / chromatic aberration）。当前 `Camera` 没有 `PostProcessing` 入口，留待 Render/VFX 层补齐。
- GPU instancing / static shared-mesh 等性能优化。当前每个 viewport 是独立 Camera3d，多 viewport 场景需要评估 GPU 成本。
- 透视相机与正交相机以外的视点（如鱼眼、cubemap）。
- 内置程序化相机动画（orbit / spin / dolly）。当前由业务层通过 `set_preview3d_camera_transform` 驱动。
